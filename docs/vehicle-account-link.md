
# 차량과 운전자 계정 연결

마중은 등록된 차량과 운전자 계정을 연결하여 차량 앱에서 해당 운전자의 계정 및 픽업 기능을 사용할 수 있도록 한다.

일반 운전자의 최초 연결은 차량 QR을 통해 등록과 계정 연결을 함께 진행한다. 이 문서는 **이미 등록된 차량의 계정 연결, 조회 및 해제 절차**를 설명한다.

- [차량 QR 최초 연결](vehicle-enrollment.md)
- [관리자 차량 등록 및 권한 철회](vehicle-registration.md)

관리자 일회용 등록 코드는 내부 관리·시험 절차이며 일반적인 사용자 시작 단계가 아니다.

또한 차량과 운전자 계정을 연결하는 QR은 탑승자 사람 연결이나 픽업 요청에 사용하지 않는다.

---

## 1. 계정 연결 기준

차량과 운전자 계정은 다음 관계를 유지한다.

| 항목 | 정책 |
| --- | --- |
| 차량당 운전자 계정 | 1개 |
| 운전자 계정당 차량 | 여러 대 허용 |
| 탑승자 수 | 차량 계정 연결 수와 무관 |
| 연결 방식 | 차량 QR + 카카오 로그인 + 차량 승인 |
| QR 유효 시간 | 5분 |
| 기존 연결 교체 | 먼저 기존 계정 연결 해제 |
| 계정 변경 요청 | 로그인 세션 및 CSRF 필요 |

차량에는 한 번에 하나의 운전자 계정만 연결할 수 있다.

하나의 운전자 계정이 여러 차량에 연결되는 것은 허용한다.

차량 계정 연결 관계와 개별 픽업의 참여자 수는 별도로 관리한다.

---

## 2. 계정 연결 흐름

### 사용자 절차

1. 차량 앱에서 계정 연결 QR 생성
2. 운전자 휴대전화로 QR 열기
3. `/account` 페이지에서 카카오 로그인
4. 필요한 경우 닉네임 설정
5. 휴대전화에서 차량 연결 요청
6. 차량 화면에서 요청자의 닉네임과 마중 ID 확인
7. 운전자가 차량에서 연결 승인
8. 서버에서 차량과 계정 연결 완료

**휴대전화에서 연결을 요청한 것만으로 차량 계정 연결이 완료되지는 않는다.**

차량 화면에서 요청자를 직접 확인하고 승인해야 한다.

### 처리 흐름

```text
차량 앱                  마중 서버                  휴대전화
   │                         │                          │
   │ 계정 연결 QR 요청       │                          │
   ├────────────────────────>│                          │
   │                         │                          │
   │ 연결 요청 정보          │                          │
   │<────────────────────────┤                          │
   │                         │                          │
   │ QR 표시                 │                          │
   │                         │                          │
   │                         │<─────────────────────────┤
   │                         │   QR 열기·카카오 로그인  │
   │                         │                          │
   │                         │<─────────────────────────┤
   │                         │   계정 연결 요청         │
   │                         │                          │
   │ 연결 요청 상태 확인     │                          │
   ├────────────────────────>│                          │
   │                         │                          │
   │ 닉네임·마중 ID 확인     │                          │
   │<────────────────────────┤                          │
   │                         │                          │
   │ 차량에서 최종 승인      │                          │
   ├────────────────────────>│                          │
   │                         │                          │
   │                         │ 차량·계정 연결 생성      │
   │                         │                          │
   │ 연결 결과 확인          │                          │
   │<────────────────────────┤                          │
```

차량 앱은 기존 차량 접근 권한을 사용하며, 휴대전화는 로그인된 계정의 세션으로 요청한다.

## 3. 차량 API

등록된 차량은 장치 접근 권한으로 계정 연결을 관리한다.

| Method | API | 기능 |
| --- | --- | --- |
| `POST` | `/api/v1/vehicles/account-link/challenges` | 계정 연결 QR 요청 생성 |
| `GET` | `/api/v1/vehicles/account-link` | 현재 연결 상태 및 요청 확인 |
| `POST` | `/api/v1/vehicles/account-link/confirm` | 연결 요청자 확인 후 승인 |
| `DELETE` | `/api/v1/vehicles/account-link` | 현재 운전자 계정 연결 해제 |

### QR 생성

```http
POST /api/v1/vehicles/account-link/challenges
```

서버는 5분 동안 유효한 일회용 연결 요청을 생성한다.

새로운 QR을 생성하면 기존 QR은 무효화한다.

QR 원본 코드는 데이터베이스에 저장하지 않는다.

### 연결 상태 조회

```http
GET /api/v1/vehicles/account-link
```

차량은 현재 연결된 운전자 계정과 대기 중인 연결 요청 상태를 확인한다.

### 연결 승인

```http
POST /api/v1/vehicles/account-link/confirm
```

운전자는 차량에 표시된 요청자의 닉네임과 마중 ID를 확인한 뒤 승인한다.

서버는 현재 차량 권한과 연결 요청의 유효성을 검사하여 계정을 연결한다.

### 계정 연결 해제

```http
DELETE /api/v1/vehicles/account-link
```

현재 차량에 연결된 운전자 계정 관계를 해제한다.

이 작업은 차량 자체의 등록 권한을 철회하는 기능이 아니다.

## 4. 휴대전화 계정 API

휴대전화는 카카오 로그인으로 생성된 웹 세션을 사용한다.

| Method | API | 기능 |
| --- | --- | --- |
| `GET` | `/api/v1/vehicle-links` | 내 계정에 연결된 차량 목록 조회 |
| `POST` | `/api/v1/vehicle-links/requests` | QR을 이용한 계정 연결 요청 |
| `GET` | `/api/v1/vehicle-links/requests/{id}` | 연결 요청 상태 조회 |
| `POST` | `/api/v1/vehicle-links/requests/{id}/cancel` | 연결 요청 취소 |
| `DELETE` | `/api/v1/vehicle-links/{vehicleId}` | 내 계정과 차량 연결 해제 |

계정 연결 변경 요청에는 유효한 로그인 세션과 CSRF 검증이 필요하다.

### 연결 요청

```http
POST /api/v1/vehicle-links/requests
```

휴대전화에서 QR의 일회용 코드를 사용해 현재 로그인된 계정의 연결 요청을 생성한다.

서버는 QR의 유효성과 기존 요청 여부를 확인한다.

### 요청 상태 확인

```http
GET /api/v1/vehicle-links/requests/{id}
```

현재 계정으로 제출한 연결 요청 상태를 조회한다.

### 요청 취소

```http
POST /api/v1/vehicle-links/requests/{id}/cancel
```

차량에서 최종 승인하기 전 연결 요청을 취소할 수 있다.

### 연결된 차량 조회 및 해제

```http
GET /api/v1/vehicle-links
```

```http
DELETE /api/v1/vehicle-links/{vehicleId}
```

로그인된 계정에 연결된 차량을 확인하고 해당 연결 관계를 해제한다.

## 5. QR 코드 보안

### 유효 시간

계정 연결 QR은 생성 후 5분 동안 유효하다.

시간이 만료된 QR은 새로운 연결에 사용할 수 없다.

새로운 QR이 발급되면 이전 QR을 무효화한다.

### 코드 저장

QR 원본 코드는 서버 데이터베이스에 저장하지 않는다.

차량 앱에서는 연결에 필요한 일회용 코드를 메모리에만 보관한다.

차량의 장치 접근 권한은 Android Keystore 기반 암호화 저장소에 보관한다.

QR 연결 코드와 차량 장치 접근 권한은 서로 다른 정보다.

### 웹 브라우저 처리

휴대전화는 QR을 통해 전달된 연결 정보를 URL fragment에서 읽는다.

이후 fragment를 주소에서 제거한다.

카카오 OAuth2 로그인 중 페이지가 이동하더라도 절차를 이어갈 수 있도록 해당 탭의 `sessionStorage`에 필요한 정보를 임시 보관한다.

다음 위치에는 일회용 연결 코드를 기록하지 않는다.

- `localStorage`
- 브라우저 디버그 로그
- 서버 진단 로그
- 공개 오류 보고
- 시연 캡처

`sessionStorage`는 OAuth 로그인 왕복을 위한 임시 저장소이며, 장기적인 인증 정보 저장소로 사용하지 않는다.

## 6. 중복 연결 및 접근 제한

### 동일 QR의 다른 계정 사용

이미 다른 계정이 요청한 QR로 다시 연결을 시도하면 서버는 충돌 응답을 반환한다.

```http
409 Conflict
```

동일한 QR을 여러 계정이 선점하거나 중복 연결하지 못하도록 제한한다.

### 다른 차량의 요청 접근

다른 차량의 권한으로 해당 연결 요청을 확인하려 하면 서버가 접근을 차단한다.

```http
410 Gone
```

차량 권한이 있다고 해서 다른 차량의 연결 요청을 조회하거나 승인할 수 있는 것은 아니다.

### 이미 연결된 차량

차량에 운전자 계정이 연결된 경우 먼저 기존 연결을 해제해야 한다.

새로운 QR을 이용해 기존 계정을 임의로 덮어쓰지 않는다.

### 차량과 계정의 관계

한 차량에는 하나의 운전자 계정만 연결한다.

반대로 하나의 운전자 계정이 여러 차량에 연결되는 것은 허용한다.

이 제약은 서버에서 검사하며, 차량 화면의 표시 여부에만 의존하지 않는다.

## 7. 계정 연결 해제와 권한 철회

마중은 차량 등록 권한, 운전자 계정 연결 및 픽업 접근 권한을 별도로 관리한다.

| 작업 | 의미 |
| --- | --- |
| 운전자 계정 연결 해제 | 차량과 운전자 계정 사이의 연결 관계 해제 |
| 차량 등록 권한 철회 | 해당 차량 장치의 서비스 접근 권한 철회 |
| 픽업 종료·취소 | 개별 픽업의 진행 및 공유 종료 |
| 탑승자 연결 종료 | 개별 탑승자의 픽업 참여 종료 |

운전자 계정을 연결 해제했다고 해서 차량 등록 권한까지 자동으로 철회한 것으로 판단하지 않는다.

또한 계정 연결 해제가 기존 픽업의 초대 권한 철회나 픽업 종료를 대신하지 않는다.

관리자에 의한 차량 권한 철회는 기존 차량 등록 관리 API를 사용한다.

[관리자 차량 등록 및 권한 관리](vehicle-registration.md)

## 8. 최초 등록과 기존 차량 연결의 차이

| 항목 | 차량 최초 연결 | 기존 차량 계정 연결 |
| --- | --- | --- |
| 대상 | 아직 등록되지 않은 차량 | 이미 등록된 차량 |
| 시작 방법 | 최초 연결 QR | 계정 연결 QR |
| 차량 장치 권한 | 최초 연결 절차에서 설정 | 기존 권한 사용 |
| 휴대전화 로그인 | 카카오 로그인 | 카카오 로그인 |
| 차량 최종 승인 | 필요 | 필요 |
| 주요 목적 | 차량 등록 및 운전자 연결 | 기존 차량의 운전자 연결 관리 |
| 관련 문서 | `vehicle-enrollment.md` | 현재 문서 |

일반 사용자는 [차량 최초 연결](vehicle-enrollment.md)을 기준으로 시작한다.

이 문서의 계정 연결 API는 기존에 등록한 차량의 운전자 계정 관계를 관리할 때 사용한다.

## 9. 검증 기준

기능 변경 시 다음 조건을 우선 확인한다.

### QR 및 요청 처리

- QR의 5분 유효 시간
- 새로운 QR 발급 시 이전 QR 무효화
- 원본 코드의 DB 저장 방지
- 다른 계정의 중복 요청 차단
- 다른 차량의 요청 확인 차단

### 계정 연결

- 휴대전화 요청만으로 연결되지 않음
- 차량 승인 이후 연결 생성
- 차량당 운전자 계정 1개 제한
- 계정당 여러 차량 허용
- 이미 연결된 차량의 임의 계정 변경 차단

### 인증 및 접근 권한

- 웹 세션 및 CSRF 검증
- 차량 장치 권한 확인
- 계정별 차량 목록 접근 제한
- 계정 연결 해제와 차량 권한 철회 구분

### 실기기 확인

- 실제 휴대전화 QR 스캔
- 카카오 OAuth2 로그인 복귀
- `sessionStorage` 기반 연결 절차 유지
- 차량 화면의 요청자 표시와 승인
- 앱 재실행 및 연결 해제 후 상태 반영

이 항목들은 기능 변경 시 확인할 검증 기준이다. 별도의 실행 결과가 없는 항목을 테스트 통과로 기록하지 않는다.

## 문서 관리 기준

이 문서는 이미 등록된 차량과 운전자 계정의 연결·조회·해제 절차를 설명한다.
