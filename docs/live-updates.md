# 픽업 상태 갱신

웹이 픽업 중일 때 SSE 연결을 열고, 변경 신호가 오면 기존 API로 최신 상태를 다시 읽는다. 위치와 ETA는 이 조회 응답의 유효기간으로 표시한다. 스트림에서 받은 예전 값을 새 정보로 되살리지 않는다.

- 링크로 참여: `GET /api/v1/pickups/{id}/events`, 참여 토큰은 Authorization 헤더
- 로그인한 탑승자: `GET /api/v1/ride-requests/{id}/events`, 기존 HttpOnly 세션 쿠키
- `changed` 이벤트의 데이터는 `refresh` 한 단어다. 위치·토큰·개인정보를 이벤트에 싣지 않는다.
- 재연결 시 전체 상태를 다시 읽는다. 서버에 이벤트 이력을 보관하지 않는다.
- 연결 중에도 약 1초마다 권한과 현재 상태를 검사한다. 연결 해제·세션 종료·픽업 종료 시 스트림을 닫는다.
- 변경이 없으면 15초마다 연결 유지 신호를 보낸다. 25분 뒤에는 연결을 새로 연다.
- 전체 최대 64개, 픽업 또는 요청 한 건당 최대 4개 연결로 제한한다.

현재는 서버가 DB 상태를 약 1초마다 비교해 변경 신호를 만든다. DB 변경 이벤트를 직접 발행하는 구조나 Kafka를 도입한 상태는 아니다. 팀 시험 규모에서 먼저 연결·권한·복구를 검증하며, 사용량이 커지면 이 비교 방식을 바꿀 수 있다.

웹은 연결이 끊기거나 SSE를 사용할 수 없으면 진행 중 픽업을 3초마다 조회한다. SSE가 연결돼도 30초마다 전체 상태를 확인한다. 화면을 숨기거나 나가면 연결을 닫고 돌아오면 다시 확인한다. 새 초대와 요청 목록은 기존 조회를 유지한다.

웹 배포 파일 목록과 서버 설치 파일 목록 모두 `stream.js`를 포함해야 한다. 프록시는 `text/event-stream`을 버퍼링하지 않아야 한다. 서버를 재시작해도 웹은 재연결과 전체 조회로 복구한다.
