# 도착 전·차량 도착 알림

탑승자가 알림을 켜면 도착 약 3분 전과 실제 `ARRIVED` 전환 때 각각 한 번 발송을 시도한다. 화면 안의 도착 배너는 알림 권한과 관계없이 표시한다. 푸시 서비스가 요청을 받았다는 사실만으로 휴대전화 표시나 운전자 확인을 보장하지 않는다.

## 언제 보내나

| 알림 | 발송 조건 | 중복 방지 |
| --- | --- | --- |
| 도착 전 `APPROACHING` | ACTIVE, 최신 차량 정보의 ETA ≤ 180초 | 장소 버전별 `notified_at` 조건부 갱신 |
| 차량 도착 `ARRIVED` | 차량의 도착 처리로 서버 상태 변경 | 장소 버전별 `arrived_notified_at` 조건부 갱신 |

ETA가 0이 돼도 도착으로 바꾸지 않는다. 도착 처리 API가 별도로 필요하다. 구독을 다시 등록해도 발송 기록은 지우지 않는다. 장소가 확정 변경되면 새 버전의 발송 기록으로 시작한다.

발송은 DB 커밋 뒤 실행한다. 실행 직전에 구독 주소·장소 버전을 다시 확인하고, 취소·완료·권한 해제로 구독이 삭제됐으면 보내지 않는다. 로컬 대기 중 실제 도착이 처리됐다면 앞선 도착 전 알림은 건너뛴다. 이미 외부 서비스에 보낸 푸시는 회수할 수 없다.

전송 실패는 자동 재발송하지 않는다. ‘각 한 번’은 최대 시도 횟수다. 404·410 응답의 구독은 삭제한다. 기기 실수신은 별도로 검증해야 한다.

## 구독 API

- 초대 참여: `PUT /api/v1/pickups/{id}/arrival-push` — 탑승자 토큰
- 로그인 참여: `PUT /api/v1/ride-requests/{id}/arrival-push` — 세션·CSRF
- 같은 경로의 `DELETE` — 해당 픽업 구독 삭제

```json
{"endpoint":"브라우저가 발급한 HTTPS 주소","p256dh":"브라우저 공개 키","auth":"브라우저 암호화 인증 값"}
```

`p256dh`와 `auth`는 함께 보내야 한다. 서버는 키 길이·형식과 입력 길이를 검사한다. 주소는 기존 PushEndpoint의 HTTPS·443·서비스 호스트 허용 목록을 사용하고 리다이렉트를 따라가지 않는다. 구독 주소와 암호화 인증 값은 로그·응답·문서에 원문을 남기지 않는다.

이전 웹의 endpoint-only 요청도 받는다. 이전 구독은 내용 없는 도착 전 알림만 유지하므로 새 웹이 기존 허용 구독의 암호화 정보를 자동으로 보완한다. 보완에 실패하면 알림을 껐다 켜 명시적으로 다시 등록할 수 있다. 서버 교체를 위해 기존 구독을 강제로 삭제하지 않는다.

## 암호화와 연결 화면

RFC 8291 `aes128gcm` 암호화를 사용한다. VAPID 개인 키는 서버 환경변수에만 둔다. payload에는 알림 종류·공개 픽업 ID·동일 서비스의 경로·발송 시각만 포함한다. 이름·위치·초대 토큰·로그인 토큰은 넣지 않는다.

- 초대 참여 알림: `/?pickup={픽업 ID}`. 같은 주소의 기존 탭을 먼저 찾는다. 새 탭에는 sessionStorage의 참여 권한이 없으므로 원래 탭 또는 초대 링크로 돌아가는 안내를 제공한다.
- 로그인 알림: `/account?request={요청 ID}`. 로그인 후 해당 요청으로 이동한다.
- 허용되지 않은 주소는 `/account`로 처리한다. 알림만으로 접근 권한을 부여하지 않는다.

새 알림의 TTL은 60초이며 웹에서도 오래된 발송 시각을 검사한다. 기존 내용 없는 알림의 TTL은 600초로 유지한다. 브라우저·OS·기기 시각·네트워크 조건에 따라 알림이 누락되거나 늦어질 수 있다.

## 서버 설정과 DB 반영

기존 `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` 설정을 사용한다. 공개·개인 키 또는 subject가 일부만 설정되면 기동에 실패한다. 키가 전혀 없으면 기능을 끈다.

운영 DB는 백업 후 `src/main/resources/db/add-arrival-context.sql`을 먼저 적용한다. 네 컬럼을 추가하는 반복 가능한 변경이며 이전 서버도 계속 사용할 수 있다. JPA validate 전에 반영해야 한다. 새 DB에는 `initial-schema.sql`을 사용한다. 기존 DB에 initial-schema.sql 전체를 재실행하지 않는다.

2026-11-05 마중 VM의 백업·네 컬럼 추가를 확인했다. FleaFlea VM은 변경하지 않았다.

## 확인한 범위

서버 전체 시험 115개 통과. 신규 시험은 도착 전/실제 도착 분리, 중복 도착 차단, 잘못된 구독 키 거절, 토큰·좌표가 없는 payload, 로컬 HTTP 수신의 aes128gcm 암호화와 상태 응답을 확인한다. 외부 푸시 서비스의 실제 휴대전화 알림 표시는 이 시험에 포함하지 않는다.

사용 라이브러리: [webpush-java](https://github.com/web-push-libs/webpush-java). 전송은 리다이렉트를 끄고 연결 5초·응답 8초로 제한한 기존 HTTP 클라이언트를 사용한다.
