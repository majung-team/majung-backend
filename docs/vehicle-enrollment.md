
# 차량 최초 연결 — QR 기반 계정 등록

마중은 차량에 표시된 QR코드를 운전자 본인의 휴대전화로 열어 차량과 계정을 처음 연결한다.

일반적인 최초 연결 과정에서 관리자에게 별도의 등록 코드를 발급받을 필요는 없다.

운전자는 카카오 로그인과 닉네임 설정을 완료한 뒤 연결을 요청하고, 차량 화면에서 연결할 계정을 직접 확인하여 승인한다.

기존에 등록된 차량은 최초 등록 과정을 반복하지 않는다.

관리자 일회용 등록 코드 API는 내부 시험 및 관리 목적으로 별도 유지한다.

> 이 기능은 마중 서비스에서 차량 앱과 운전자 계정의 접근 권한을 연결하는 절차다. 실제 차량의 VIN이나 법적 소유권을 인증하는 기능은 아니다.

---

## 1. 최초 연결 흐름

차량과 휴대전화, 서버가 함께 참여하는 절차다.

| 단계 | 주체 | 동작 |
| --- | --- | --- |
| 1 | 차량 | 5분 동안 유효한 연결 요청 생성 |
| 2 | 차량 | 연결용 QR코드 표시 |
| 3 | 휴대전화 | QR을 열고 카카오 로그인 및 닉네임 설정 |
| 4 | 휴대전화 | 로그인된 계정으로 차량 연결 요청 |
| 5 | 차량 | 연결 요청자의 닉네임과 마중 ID 확인 |
| 6 | 운전자 | 차량 화면에서 본인 계정인지 최종 확인 |
| 7 | 서버 | 차량과 운전자 계정 연결 생성 |

### 전체 흐름

```text
차량 앱                마중 서버                 휴대전화
   │                       │                         │
   │ 연결 요청 생성        │                         │
   ├──────────────────────>│                         │
   │                       │                         │
   │ 요청 ID·일회용 코드   │                         │
   │<──────────────────────┤                         │
   │                       │                         │
   │ QR 표시               │                         │
   │                       │                         │
   │                       │<────────────────────────┤
   │                       │    QR 열기 및 로그인     │
   │                       │                         │
   │                       │<────────────────────────┤
   │                       │    차량 연결 요청        │
   │                       │                         │
   │ 연결 요청 상태 조회   │                         │
   ├──────────────────────>│                         │
   │                       │                         │
   │ 닉네임·마중 ID        │                         │
   │<──────────────────────┤                         │
   │                       │                         │
   │ 운전자 최종 확인      │                         │
   │                       │                         │
   │ 연결 승인             │                         │
   ├──────────────────────>│                         │
   │                       │                         │
   │                       │ 차량·계정 연결 생성     │
   │                       │                         │
   │ 연결 결과 확인        │                         │
   │<──────────────────────┤                         │
```

휴대전화에서 QR을 열었다는 사실만으로 차량 연결이 완료되지 않는다.

차량에서 연결 요청자를 확인하고 최종 승인해야 서버가 차량과 계정의 연결을 생성한다.

---

## 2. 차량 연결 요청 생성

차량 앱은 서버에 최초 연결 요청을 생성한다.

### API

```http
POST /api/v1/vehicles/enrollments
```

서버는 연결 요청 ID와 일회용 QR 코드를 발급한다.

### QR에 포함하는 정보

QR에는 다음 정보만 포함한다.

- 연결 요청 ID
- 일회용 `code`

장치의 비밀 권한인 `deviceToken`은 QR에 포함하지 않는다.

### 장치 비밀 보관

`deviceToken`은 차량 앱의 암호화 저장소에만 보관한다.

휴대전화와 QR을 통해 전달하지 않는다.

이 단계에서는 아직 차량 계정 연결이나 픽업 접근 권한이 생성되지 않는다.

### 유효 시간

연결 요청은 생성 후 5분 동안 유효하다.

만료된 요청은 새로운 차량 연결에 사용할 수 없다.

---

## 3. 휴대전화에서 연결 요청

운전자는 차량에 표시된 QR을 휴대전화로 연다.

### 연결 주소

```text
https://majung.cloud/account#enroll/{id}/{code}
```

URL의 fragment에는 연결 요청 ID와 일회용 코드가 포함된다.

### 사용자 진행 순서

1. 차량의 QR코드 스캔
2. 마중 계정 페이지 열기
3. 카카오 로그인
4. 필요한 경우 닉네임 설정
5. 차량 연결 요청 제출
6. 차량 화면에서 최종 확인 대기

### 로그인 중 연결 정보 보관

웹은 URL fragment에서 연결 정보를 읽은 후 주소 표시줄의 fragment를 제거한다.

로그인 과정에서 화면이 이동하더라도 연결 절차를 이어갈 수 있도록 필요한 정보를 `sessionStorage`에 임시 보관한다.

연결 코드를 URL에 계속 노출하거나 별도의 장기 로그인 자격 증명으로 사용하지 않는다.

### 연결 요청 API

```http
POST /api/v1/vehicle-links/enrollments/{id}
```

요청 본문:

```json
{
  "code": "일회용 연결 코드"
}
```

이 API에는 다음 조건이 필요하다.

- 유효한 웹 로그인 세션
- CSRF 검증
- 만료되지 않은 연결 요청
- 올바른 일회용 코드

로그인된 계정이 연결을 요청하면 서버가 해당 요청과 계정을 연결한다.

동일한 QR을 다른 계정이 중복으로 가져갈 수 없도록 제한한다.

---

## 4. 차량에서 계정 확인

휴대전화에서 연결 요청이 제출되면 차량 앱은 해당 연결 요청을 조회한다.

### 연결 상태 조회

```http
GET /api/v1/vehicles/enrollments/{id}
```

차량은 장치 Bearer 권한을 사용한다.

서버는 권한이 확인된 차량에 연결 요청 상태와 요청자 정보를 제공한다.

차량에서 표시할 정보:

- 연결 요청자의 닉네임
- 마중 ID
- 연결 요청 상태

### 운전자 최종 확인

운전자는 차량 화면에 표시된 계정이 자신의 계정인지 확인한다.

다른 사람의 계정이 표시됐다면 승인하지 않는다.

차량에서 최종 확인해야만 연결이 완료된다.

### 연결 승인 API

```http
POST /api/v1/vehicles/enrollments/{id}/confirm
```

요청 본문:

```json
{
  "majungId": "확인한 마중 ID"
}
```

서버는 확인한 계정과 연결 요청을 검증한 뒤 차량과 운전자 계정의 연결을 생성한다.

기존 장치 비밀을 해당 차량의 권한으로 사용한다.

새로운 차량 권한을 휴대전화나 QR에 전달하지 않는다.

---

## 5. 연결 요청 상태와 취소

### 차량 상태 확인

차량은 다음 API로 현재 연결 요청 상태를 확인한다.

```http
GET /api/v1/vehicles/enrollments/{id}
```

### 차량 연결 요청 취소

```http
POST /api/v1/vehicles/enrollments/{id}/cancel
```

차량은 장치 Bearer 권한을 사용하여 자신의 요청을 취소한다.

### 휴대전화 조회 및 취소

휴대전화의 연결 상태 조회·취소도 관련 `vehicle-links/enrollments` 경로에서 처리한다.

휴대전화 요청에는 웹 로그인 세션과 해당 요청에 대한 접근 권한 확인이 필요하다.

취소된 요청은 종료되며 다른 계정이 같은 QR을 재사용할 수 없다.

---

## 6. 중복 요청 및 재시도 처리

네트워크 연결이 끊기거나 API 응답을 받지 못한 경우에도 동일한 차량 연결이 중복 생성되지 않도록 처리한다.

### 연결 완료 응답을 받지 못한 경우

차량에서 최종 승인 요청을 보낸 뒤 응답이 유실될 수 있다.

이때 새로운 차량 연결을 다시 생성하지 않고 기존 요청 상태를 조회한다.

```http
GET /api/v1/vehicles/enrollments/{id}
```

서버에서 이미 연결이 완료됐다면 차량은 해당 결과를 확인하여 권한을 저장할 수 있다.

### 승인 재시도

동일한 요청을 재확인하더라도 새로운 차량을 중복 생성하지 않는다.

기존에 완료된 연결과 동일한 차량을 반환한다.

### 다른 계정의 중복 요청

연결 요청이 특정 계정과 연결된 뒤에는 다른 계정이 같은 QR을 사용하여 기존 요청을 가져갈 수 없다.

동시 요청에서도 하나의 계정만 해당 연결 요청을 사용할 수 있도록 제한한다.

### 취소된 요청

휴대전화에서 연결을 취소하면 해당 요청은 종료된다.

취소한 QR을 다른 계정이 다시 사용하여 연결을 진행할 수 없다.

## 7. 연결 요청 만료 및 정리

최초 연결 QR과 완료 후 복구용 기록은 서로 다른 유효 기간을 사용한다.

| 구분 | 기준 |
| --- | --- |
| 미완료 연결 요청 | 생성 후 5분 |
| 완료된 연결 요청의 장치 복구 기록 | 만료 시각에서 최대 약 1시간 후 정리 |

### 미완료 요청

5분이 지나면 QR을 이용한 신규 연결을 진행할 수 없다.

만료된 QR을 다시 활성화하지 않는다.

필요하면 차량에서 새로운 연결 요청을 생성한다.

### 완료 후 복구 기록

차량이 연결 완료 응답을 받지 못한 경우 기존 요청을 조회할 수 있도록 복구용 기록을 일정 기간 유지한다.

해당 기록은 만료 시각에서 최대 약 1시간 뒤 정리한다.

이는 완료된 연결을 복구하기 위한 임시 기록이며, QR 자체의 유효 시간을 연장하는 것은 아니다.

## 8. 인증 및 보안 기준

### QR 코드와 장치 비밀 분리

| 정보 | QR 포함 | 저장 및 사용 목적 |
| --- | --- | --- |
| 연결 요청 ID | 포함 | 연결 요청 식별 |
| 일회용 `code` | 포함 | 휴대전화 연결 요청 검증 |
| `deviceToken` | 포함하지 않음 | 차량 장치 권한 |
| 픽업 접근 토큰 | 포함하지 않음 | 개별 픽업 접근 |

차량 등록을 위한 정보와 실제 픽업의 접근 권한을 분리한다.

### 서버 저장 방식

서버는 QR 코드 및 장치 비밀을 해시 형태로 저장한다.

원문 비밀 값을 그대로 저장하거나 진단 로그에 출력하지 않는다.

### 웹 인증

휴대전화의 연결 요청에는 로그인 세션과 CSRF 검증을 적용한다.

QR을 소유하고 있다는 사실만으로 다른 계정의 기존 연결을 변경할 수 없다.

### 차량 승인

차량의 최종 확인에는 장치 Bearer 권한을 사용한다.

운전자가 연결할 계정을 직접 확인한 뒤 승인하도록 구성한다.

### 인증 범위

이 기능이 검증하는 것은 마중 서비스 안의 차량 앱과 운전자 계정 연결이다.

다음 항목을 인증하는 기능은 아니다.

- 실제 차량 VIN
- 자동차 등록원부
- 법적 차량 소유권
- 차량 제조사의 소유자 인증

## 9. 기존 데이터베이스 반영

기존 마중 운영 환경에 적용할 때는 데이터베이스 마이그레이션을 먼저 수행한다.

### 적용 SQL

```text
deploy/vehicle-enrollment.sql
```

### 배포 순서

1. 운영 PostgreSQL 백업
2. 신규 테이블 추가 SQL 검토
3. `vehicle-enrollment.sql` 적용
4. 애플리케이션 DB 사용자 권한 부여
5. 신규 백엔드 배포
6. 모바일 웹 배포
7. 신규 차량 APK에서 연결 시험

### DB 권한

신규 테이블에 다음 권한을 부여한다.

- `SELECT`
- `INSERT`
- `UPDATE`
- `DELETE`

이번 변경은 기존 테이블을 삭제하거나 변경하는 방식이 아니라 신규 테이블을 추가하는 방식이다.

따라서 이전 서버와의 호환성을 유지하도록 구성했다.

### 배포 시 주의사항

DB → 서버 → 웹 순서로 반영하고, QR 기반 최초 연결을 지원하는 차량 APK를 사용한다.

코드 배포를 되돌린다고 해서 추가한 테이블이 자동으로 삭제되는 것은 아니다.

운영 환경의 DB 변경은 백업 및 스키마 호환성을 확인한 뒤 진행한다.

## 10. 테스트 및 검증

백엔드에서는 연결 요청의 인증·권한·만료·재시도 처리를 중심으로 시험했다.

### 인증 및 접근 권한

- 승인 전 권한 사용 차단
- QR 코드와 장치 비밀 분리
- 다른 계정의 연결 요청 접근 차단
- 다른 차량의 요청 조회 차단
- 로그인 세션 검증
- CSRF 검증

### 연결 및 중복 처리

- 동시 연결 요청에서 한 계정만 연결
- 연결 완료 후 같은 요청 재전송
- 중복 차량 생성 방지
- 완료 응답 유실 후 상태 재조회
- 취소된 요청 재사용 차단

### 만료 및 권한 철회

- 정확한 5분 만료 경계
- 만료된 QR 사용 차단
- 연결 취소
- 장치 권한 철회
- 완료된 요청의 복구 처리

### 별도 검증 범위

백엔드 자동화 테스트와 다음 실기기 시험은 구분한다.

- 실제 휴대전화 카메라의 QR 스캔
- 카카오 로그인 왕복 과정
- 실제 휴대전화 브라우저의 `sessionStorage` 동작
- 차량 앱과 휴대전화의 전체 최초 연결 흐름
- 실차에서의 계정 연결

서버 테스트 통과를 실제 휴대전화나 실차 연동 검증 완료로 표현하지 않는다.

## 문서 관리 기준

이 문서는 차량 QR 기반 최초 연결의 API 흐름, 인증 및 권한 처리, 유효 시간과 배포 절차를 설명한다.

다음 항목은 별도로 구분하여 기록한다.

- QR 연결 요청과 차량 장치 권한
- 차량 계정 연결과 개별 픽업 권한
- 휴대전화의 연결 요청과 차량의 최종 승인
- 미완료 QR 만료와 완료 후 복구 기록 정리
- 백엔드 자동화 테스트와 실제 기기 연동 시험

API 경로나 인증 정책을 변경하는 경우 차량 앱, 모바일 웹 및 서버의 호환성을 함께 확인한다.
