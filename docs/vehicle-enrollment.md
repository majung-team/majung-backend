# 휴대전화로 차량 처음 연결하기

관리자에게 코드를 받지 않고 차량 QR을 운전자 휴대전화로 열어 연결한다. 기존에 등록된 차량은 다시 등록할 필요가 없다. 관리자 코드 API는 내부 시험용으로 유지한다.

1. 차량: `POST /api/v1/vehicles/enrollments`로 5분짜리 연결 요청을 만든다.
2. QR에는 연결 요청 ID와 일회용 `code`만 넣는다. 별도 `deviceToken`은 차량의 암호화 저장소에만 보관한다. 이 시점에는 픽업 권한이 없다.
3. 휴대전화: `/account#enroll/{id}/{code}`를 열어 카카오 로그인·닉네임 설정 후 연결을 요청한다. fragment는 페이지에서 지우고 로그인 왕복 동안 sessionStorage에 보관한다.
4. `POST /api/v1/vehicle-links/enrollments/{id}`에 `{code}`를 보낸다. 로그인 세션과 CSRF가 필요하다. 같은 QR을 다른 계정이 가져갈 수 없다.
5. 차량: `GET /api/v1/vehicles/enrollments/{id}`에 장치 Bearer 권한을 보내 닉네임·마중 ID를 확인한다. 사용자가 본인임을 확인하면 `/confirm`에 `{majungId}`를 보낸다.
6. 서버가 그때 차량과 운전자 연결을 함께 만든다. 기존 장치 비밀을 해당 차량의 권한으로 사용한다. 새 권한을 휴대전화나 QR에 보내지 않는다.

장치 확인·휴대전화 조회와 취소는 각각 위 경로의 GET·POST `/cancel`을 사용한다. 장치는 연결 완료 응답을 잃어도 GET으로 확인해 권한을 저장할 수 있다. 장치 확인 재시도는 같은 차량을 반환하고 중복 생성하지 않는다. 휴대전화 취소는 요청을 끝내므로 다른 계정이 그 QR을 재사용할 수 없다.

미완료 QR은 5분 뒤 사용할 수 없다. 완료 후 장치 복구용 기록은 만료 시각에서 최대 약 1시간 뒤 정리한다. 서버는 QR과 장치 비밀을 해시로만 저장한다. 실제 차량 소유권을 인증하는 기능은 아니다.

## 배포

기존 마중 DB를 백업한 뒤 `deploy/vehicle-enrollment.sql`을 PostgreSQL에 적용하고, 앱 DB 사용자에게 새 테이블의 SELECT·INSERT·UPDATE·DELETE 권한을 부여한다. 이 변경은 테이블 추가뿐이며 이전 서버와 호환된다. DB → 서버 → 웹 순서로 배포하고 새 차량 APK를 사용한다.

## 확인

서버 테스트는 미승인 권한 차단, QR/장치 비밀 분리, 타인 요청·조회 차단, 동시 요청 1명 제한, 정확한 만료 경계·취소·재전송·철회, 로그인·CSRF를 확인한다. 실제 휴대전화 로그인과 카메라 스캔은 별도 시험한다.
