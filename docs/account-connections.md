
# 카카오 로그인 및 계정·사람 연결

마중은 카카오 OAuth2 로그인을 통해 사용자 계정을 생성하고, 닉네임과 마중 ID를 이용한 사람 검색 및 연결 기능을 제공한다.

백엔드는 Spring Security OAuth2 Client를 사용하여 인증 과정을 처리한다. 브라우저에는 서버 세션을 사용하며, 카카오 액세스 토큰을 모바일 웹이나 차량 앱에 전달하지 않는다.

이 문서는 계정 관리 구조, API, 접근 권한, 카카오 연결 해제 처리 및 검증 결과를 정리한다.

> 최초 구현과 공개 HTTPS 검증은 2026년 10월 25일에 수행했다. 당시의 단일 서버 메모리 세션은 10월 29일 블루·그린 배포 과정에서 PostgreSQL 공유 세션으로 변경됐다. 각 시점의 구현과 검증 결과를 구분한다.

## 1. 주요 기능

| 기능 | 설명 |
| --- | --- |
| 카카오 로그인 | OAuth2 인가 코드 방식으로 사용자 인증 |
| 마중 계정 생성 | 최초 로그인 시 계정 및 마중 ID 발급 |
| 닉네임 관리 | 닉네임 최초 설정 및 변경 |
| 사용자 검색 | 닉네임 부분 검색 및 마중 ID 정확 검색 |
| 사람 연결 요청 | 다른 계정에 연결 요청 |
| 요청 관리 | 승인·거절·취소 |
| 연결 해제 | 승인된 계정 관계 종료 |
| 카카오 연결 해제 | 웹훅 수신 후 계정 및 연결 관계 정리 |

사람 연결은 사용자 사이의 관계를 관리하는 기능이다.

연결을 승인했다고 해서 새로운 픽업이 생성되거나 차량 위치·ETA가 공개되지는 않는다.

## 2. 카카오 OAuth2 로그인

### 인증 구조

서버에서 Spring Security OAuth2 Client를 사용하여 다음 과정을 처리한다.

1. 웹에서 로그인 시작
2. 서버가 OAuth2 인가 요청 생성
3. 카카오 인증 및 사용자 동의
4. 등록된 서버 콜백으로 복귀
5. 인가 코드 및 `state` 검증
6. 서버에서 토큰 교환
7. 카카오 사용자 정보 조회
8. 마중 계정 확인 또는 생성
9. 서버 로그인 세션 생성
10. 고정된 계정 화면으로 이동

로그인 과정의 공급자 토큰은 서버에서 처리한다.

카카오 액세스 토큰이나 Client Secret을 웹·차량 앱·URL에 전달하지 않는다.

### 로그인 이동 주소

| 상황 | 이동 주소 |
| --- | --- |
| 로그인 시작 | `/api/v1/auth/login` |
| 로그인 성공 | `/account` |
| 로그인 실패 | `/account?login=failed` |

로그인 결과는 고정된 상대 경로의 `Location` 헤더로 전달한다.

Caddy 등 프록시의 내부 Host 또는 HTTP 주소로 브라우저를 이동시키지 않는다.

### OAuth2 보안

- 인가 요청의 `state` 검증
- PKCE `S256` 적용
- 인가 코드의 서버 측 교환
- 로그인 후 세션 ID 변경
- 고정된 HTTPS Redirect URI 사용
- 공급자 오류 상세 정보의 브라우저 노출 방지

로그인 실패 시 내부 공급자 오류나 인증 비밀 값을 화면에 출력하지 않는다.

### 카카오에서 사용하는 정보

사용자 정보 조회를 통해 받은 **카카오 회원번호**를 마중 계정의 로그인 연결에 사용한다.

다음 정보는 요청하지 않는다.

- 이메일
- 프로필 사진
- 카카오 친구 목록

카카오 회원번호는 서버 내부에서 계정 식별에 사용하며, 검색 결과나 공개 사용자 프로필에 포함하지 않는다.

## 3. 로그인 세션

마중은 브라우저에 서버 세션 쿠키를 사용한다.

### 쿠키 정책

| 속성 | 설정 |
| --- | --- |
| `HttpOnly` | 활성화 |
| `Secure` | 활성화 |
| `SameSite` | `Lax` |
| 세션 유효 시간 | 8시간 |

프론트엔드에서 카카오 액세스 토큰을 직접 저장하는 구조가 아니다.

동일한 HTTPS origin에서 세션 쿠키를 이용해 API에 접근한다.

### 세션 저장 방식 변경

**2026년 10월 25일 최초 구현**

- 단일 서버 메모리 세션 사용
- 서버 재시작 시 기존 세션 유지 불가
- 재로그인 필요

**2026년 10월 29일 블루·그린 배포 이후**

- Spring Session JDBC 사용
- PostgreSQL 공유 세션 저장
- Blue·Green 서버가 동일한 세션 및 CSRF 정보 사용

현재 공유 세션 구조는 다음 테이블을 사용한다.

```text
SPRING_SESSION
SPRING_SESSION_ATTRIBUTES
```

메모리 세션에서 JDBC 세션으로 최초 변경할 때는 기존 사용자의 재로그인이 한 번 필요할 수 있었다.

[블루·그린 배포 및 세션 전환](blue-green.md)

### 기존 차량·픽업 인증과의 구분

웹 로그인 세션은 계정 관련 API 접근에 사용한다.

기존 차량 및 픽업 Bearer 인증을 웹 로그인 세션으로 대체하지 않는다.

- 웹 계정 API: 로그인 세션
- 차량 API: 차량 접근 권한
- 픽업 운전자 API: 개별 픽업 운전자 권한
- 탑승자 API: 개별 픽업 접근 권한

## 4. 계정 API

| Method | 경로 | 기능 |
| --- | --- | --- |
| `GET` | `/api/v1/auth/session` | 로그인 설정·계정 정보·CSRF 확인 |
| `GET` | `/api/v1/auth/login` | 카카오 로그인 시작 |
| `POST` | `/api/v1/auth/logout` | 로그아웃 |
| `GET` | `/api/v1/accounts/me` | 내 계정 조회 |
| `PATCH` | `/api/v1/accounts/me` | 닉네임 설정 및 변경 |
| `GET` | `/api/v1/accounts/search?query=...&page=0` | 사용자 검색 |

### CSRF 처리

계정 변경 요청에는 세션 API에서 받은 CSRF 토큰을 사용한다.

```http
X-CSRF-TOKEN: <csrfToken>
```

로그아웃과 닉네임 변경 등 상태를 변경하는 요청은 세션 및 CSRF 검증을 거친다.

## 5. 마중 계정 및 ID

### 계정 생성

카카오 최초 로그인 시 서버에서 마중 계정을 생성한다.

동일한 카카오 계정으로 다시 로그인하면 기존 마중 계정을 사용한다.

로그아웃 후 재로그인하더라도 기존 마중 ID와 닉네임을 유지한다.

### 마중 ID

마중 ID는 다음 형식을 사용한다.

```text
MJ-XXXXXXXXXX
```

`MJ-` 접두사와 서버에서 생성한 무작위 16진수 10자리로 구성한다.

DB 유일성 제약으로 중복을 방지한다.

동시에 최초 로그인이 발생하거나 ID 충돌이 생기면 트랜잭션 롤백 후 재조회 또는 재시도하여 처리한다.

### 닉네임

닉네임은 중복을 허용한다.

| 항목 | 기준 |
| --- | --- |
| 길이 | 2~20자 |
| 정규화 | Unicode NFKC |
| 허용 문자 | 문자·숫자·공백·밑줄·점·하이픈 |
| 중복 닉네임 | 허용 |
| 변경 | 로그인된 본인만 가능 |

닉네임이 같아도 계정은 서로 다르다.

계정 관계는 닉네임 문자열이 아니라 내부 계정 식별자로 관리한다.

닉네임을 변경하면 연결 목록에도 변경된 이름이 반영된다.

## 6. 사람 검색

로그인한 사용자는 닉네임 또는 마중 ID로 다른 계정을 검색할 수 있다.

### 검색 API

```http
GET /api/v1/accounts/search?query=...&page=0
```

### 검색 기준

| 항목 | 기준 |
| --- | --- |
| 검색 권한 | 로그인된 계정 |
| 검색어 | 2~32자 |
| 페이지 크기 | 20건 |
| 최대 페이지 | 50 |
| 닉네임 | 부분 검색 |
| 마중 ID | 정확 검색 |

### 검색 결과

검색 결과에는 다음 정보만 포함한다.

- `memberId`
- `majungId`
- `nickname`

검색 결과에서 본인 계정은 제외한다.

닉네임을 설정하지 않은 계정도 검색 결과와 새로운 연결 요청 대상에서 제외한다.

SQL 와일드카드 문자는 패턴 제어 문자가 아니라 일반 입력 문자로 처리한다.

### 검색의 의미

사용자 검색은 마중 계정을 찾는 기능이다.

검색 결과에 표시된 계정이 다음 조건을 충족한다고 보장하지 않는다.

- 등록된 차량 보유
- 현재 픽업 가능
- 특정 차량의 운전자
- 진행 중인 픽업 존재

차량과 운전자 계정 연결 및 실제 픽업 요청은 별도 기능이다.

## 7. 사람 연결 API

| Method | 경로 | 기능 |
| --- | --- | --- |
| `GET` | `/api/v1/connections?page=0` | 연결 및 요청 목록 조회 |
| `POST` | `/api/v1/connections` | 연결 요청 |
| `POST` | `/api/v1/connections/{id}/accept` | 받은 요청 승인 |
| `POST` | `/api/v1/connections/{id}/reject` | 받은 요청 거절 |
| `POST` | `/api/v1/connections/{id}/cancel` | 보낸 요청 취소 |
| `POST` | `/api/v1/connections/{id}/disconnect` | 승인된 연결 해제 |

연결 요청은 대상 `memberId`를 기준으로 생성한다.

계정 연결 변경 요청에는 웹 로그인 세션과 CSRF 검증이 필요하다.

## 8. 사람 연결 상태

연결 요청은 다음 상태로 관리한다.

| 현재 상태 | 가능한 다음 상태 |
| --- | --- |
| `PENDING` | `ACCEPTED`, `REJECTED`, `CANCELLED` |
| `ACCEPTED` | `DISCONNECTED` |

### 연결 요청

요청을 보낸 직후에는 `PENDING` 상태가 된다.

상대방이 반대 방향으로 연결 요청을 보내더라도 자동으로 승인하지 않는다.

명시적인 수락 절차가 필요하다.

### 승인·거절·취소

- 받은 사람만 승인 또는 거절 가능
- 보낸 사람만 대기 요청 취소 가능
- 승인된 연결은 양쪽에서 해제 가능

요청과 무관한 계정의 접근에는 HTTP 404를 반환한다.

### 중복 연결 방지

동일한 두 계정 사이에는 하나의 연결 관계만 유지한다.

계정 ID를 기준으로 정렬된 잠금과 DB 유일성 제약을 사용한다.

동시 요청으로 같은 연결이 중복 생성되지 않도록 처리한다.

현재 상태와 일치하는 재전송은 같은 결과를 반환한다.

### 재요청 제한

거절·취소·연결 해제 직후 반복 요청을 줄이기 위해 초기 구현에서는 24시간의 재요청 간격을 적용했다.

이는 해당 시점의 초기 제품 정책이다.

영구 차단, 사용자별 요청 수신 설정 및 차단 UI는 별도 기능으로 구분한다.

## 9. 사람 연결과 픽업의 구분

사람 연결을 승인했다고 해서 다음 동작이 자동으로 발생하지 않는다.

- 새로운 픽업 생성
- 차량 위치 공개
- ETA 접근 권한 부여
- 차량 등록 또는 소유자 연결
- 개별 픽업 토큰 발급

사람 연결은 계정 사이의 관계를 관리한다.

차량 계정 연결, 픽업 요청 및 픽업 참여는 각각 별도의 상태와 접근 권한을 사용한다.

### 개발 단계 변경

2026년 10월 25일 최초 계정 기능을 검증했을 당시에는 다음 항목이 후속 작업으로 기록되어 있었다.

- 실제 픽업 요청
- 요청 대기 순서
- 차량 운전자 계정 연결
- 개별 탑승자의 ETA 조회
- 서비스 탈퇴 UI
- 계정·차량 연결 이후의 권한 회수

이후 차량 계정 연결 및 픽업 요청 기능이 추가 개발되었다.

현재 구현 상태는 다음 문서를 기준으로 확인한다.

- [차량과 운전자 계정 연결](vehicle-account-link.md)
- [픽업 요청 및 대기열](ride-requests.md)
- [개발 현황](https://github.com/majung-team/majung/blob/main/docs/development-status.md)

## 10. 카카오 연결 해제 웹훅

카카오에서 사용자가 마중과의 연결을 해제하면 서버는 별도의 웹훅을 통해 해당 사실을 처리한다.

### 웹훅 API

```http
POST /api/v1/auth/kakao/unlink
```

이 API는 일반 브라우저의 계정 변경 요청이 아니라 카카오 연결 해제 통지 전용이다.

### 요청 검증

다음 항목을 확인한다.

- 대표 어드민 키 헤더
- 대상 카카오 앱 ID
- 요청 형식

요청의 주요 폼 필드:

- `app_id`
- `user_id`
- `referrer_type`

인증이 일치하지 않거나 다른 앱에 대한 요청은 거부한다.

### CSRF 정책

웹훅 경로에만 브라우저 CSRF 검증 예외를 적용한다.

로그아웃이나 닉네임 변경 등 다른 계정 변경 API에는 기존 CSRF 검증을 유지한다.

### 처리 흐름

```text
카카오 연결 해제 통지
          │
          ▼
  웹훅 인증·앱 ID 검사
          │
          ▼
     DB에 통지 저장
          │
          ▼
       HTTP 200
          │
          ▼
  해당 계정의 접근 차단
          │
          ▼
    주기 정리 작업
          │
          ▼
 계정·연결 관계 삭제
          │
          ▼
    작업 기록 정리
```

### 통지 저장 및 접근 차단

웹훅은 통지를 DB에 저장한 뒤 HTTP 200으로 응답한다.

저장된 연결 해제 통지가 있는 계정은 실제 삭제 작업이 끝나기 전이라도 다음 동작에서 제외한다.

- 기존 로그인 세션을 통한 접근
- 재로그인
- 사람 검색
- 새로운 연결 요청

따라서 데이터 정리 작업이 완료되기 전에도 기존 세션을 계속 사용하는 상황을 차단한다.

### 계정 및 연결 관계 삭제

5초 주기의 정리 작업에서 계정과 관련 연결 관계를 하나의 트랜잭션으로 삭제한다.

처리에 성공하면 작업 기록도 삭제한다.

삭제 중 실패하면 작업 기록을 유지하고 다음 주기에 재시도한다.

### 중복 통지 처리

다음 상황을 고려한다.

- 같은 통지 반복 수신
- 이미 삭제된 계정의 연결 해제 통지
- 정리 작업 중 오류
- 상대방 계정 보존

동일 통지의 재처리로 다른 사용자 계정이 삭제되지 않도록 한다.

---

## 11. 웹훅 응답 및 실패 처리

### 응답 시간

수신 DB 작업에는 2초 트랜잭션 제한을 적용한다.

카카오의 응답 시간 요구사항을 고려하여 설계했지만, 실제 운영 환경의 부하와 DB 장애 상황에서 응답 시간이 항상 보장되는 것은 아니다.

### 저장 실패

통지 저장 자체가 실패하면 수신 완료로 처리하지 않는다.

통지를 저장하지 못했는데도 정상 수신했다고 응답하는 방식은 피한다.

공급자가 반드시 다시 전송한다고 가정하지 않으며, 해당 오류는 운영에서 별도로 확인해야 한다.

### 운영 웹훅 주소

카카오 개발자 콘솔에는 다음 HTTPS 주소를 등록했다.

```text
https://majung.cloud/api/v1/auth/kakao/unlink
```

등록과 시험 요청 성공은 카카오가 실제 사용자 연결 해제 이벤트를 발송했다는 뜻이 아니다.

## 12. 운영 환경변수

카카오 인증과 연결 해제 웹훅에 필요한 값은 운영 서버의 환경 파일에서 관리한다.

| 환경변수 | 용도 |
| --- | --- |
| `MAJUNG_LOGIN_ENABLED` | 카카오 로그인 활성화 |
| `KAKAO_CLIENT_ID` | 카카오 REST API 키 |
| `KAKAO_CLIENT_SECRET` | 카카오 Client Secret |
| `KAKAO_ADMIN_KEY` | 연결 해제 웹훅 인증 |
| `KAKAO_APP_ID` | 연결 해제 통지의 대상 앱 확인 |
| `KAKAO_REDIRECT_URI` | 등록된 HTTPS OAuth2 콜백 |

### Redirect URI

카카오 로그인 콜백은 고정된 HTTPS 주소를 사용한다.

```text
https://majung.cloud/api/v1/auth/callback/kakao
```

### 로그인 활성화

필수 설정이 없는 기본 실행에서는 카카오 로그인을 비활성화하고 기존 픽업 API를 유지한다.

운영 설정을 완료한 뒤 다음 값을 활성화한다.

```text
MAJUNG_LOGIN_ENABLED=true
```

### OAuth2 식별자와 비밀 값

OAuth 인가 URL에 `client_id`가 포함되는 것은 표준 동작이다.

Client ID는 공개 클라이언트 식별자이며 Client Secret과 구분한다.

다음 값은 공개하지 않는다.

- Client Secret
- 관리자 키
- DB 비밀번호
- 사용자 토큰
- OAuth 인가 코드 및 `state`
- 실제 세션 쿠키

## 13. 환경 파일 및 비밀 정보 관리

배포용 설정 예시는 다음 파일에 값 없이 관리한다.

```text
deploy/server.env.example
```

실제 운영 설정은 다음 파일에서 systemd가 읽는다.

```text
/etc/majung/server.env
```

### 파일 권한

- 소유자: root
- 접근 권한: `600`
- Git 저장소 외부 보관

실제 비밀 값을 다음 위치에 복사하지 않는다.

- 저장소 내부 `.env`
- GitHub Actions 로그
- 컨테이너 또는 배포 이미지
- 웹 정적 파일
- 차량 APK
- 공개 문서 및 시연 캡처

### 설정 변경

서버 환경 파일을 수정한 뒤에는 서비스 재시작이 필요하다.

파일 내용을 통째로 출력하지 않고 필요한 변수의 설정 여부와 접근 권한만 확인한다.

기존 환경 파일을 백업하는 경우에도 접근 제한된 디렉터리를 사용한다.

## 18. 브라우저 연동 시험

**검증일: 2026년 10월 25일**

로컬 가상 공급자를 이용해 실제 브라우저에서 계정 및 사람 연결 흐름을 확인했다.

### 서버 실행

수동 브라우저 시험은 별도 옵션으로 실행한다.

```sh
MAJUNG_BROWSER_FIXTURE=true \
./gradlew test --tests '*AccountBrowserFixtureTest'
```

### 웹 실행

```sh
MAJUNG_API_PORT=18081 \
MAJUNG_WEB_PORT=18082 \
npm start
```

사용 포트:

| 구성 | 포트 |
| --- | --- |
| 로컬 API | `18081` |
| 모바일 웹 | `18082` |

위 웹 실행 명령은 웹 저장소에서 수행한다.

### 시험 계정

가상 OAuth2 공급자에서 시험 계정 1·2를 선택한다.

실제 카카오 계정이나 운영 키는 사용하지 않는다.

시험 서버는 15분 후 자동 종료된다.

JVM 임시 디렉터리에 `majung-browser-fixture.stop` 파일을 생성하면 먼저 종료할 수 있다.

일반 자동 시험에서는 해당 수동 브라우저 시험 1건을 건너뛴다.

### 확인 결과

실제 Tomcat, DB, Spring Security 및 브라우저를 사용해 다음 기능을 확인했다.

- 두 계정 로그인
- 닉네임 설정
- 사람 검색
- 연결 요청
- 요청 수락
- 연결 해제

HTTP 시험을 위한 Secure 쿠키 설정 완화는 해당 시험 클래스에만 적용했다.

배포 JAR에는 시험 클래스가 포함되지 않는다.

## 19. 공개 HTTPS 인증 검증

**검증일: 2026년 10월 25일**

운영 서버와 실제 카카오 인증 화면을 대상으로 확인했다.

### 로그인 시작 및 보안

- `/api/v1/auth/login`에서 HTTP 302 응답 확인
- 등록된 카카오 인가 화면 도달
- PKCE `S256` 포함
- 등록된 HTTPS Redirect URI 사용
- `Secure`, `HttpOnly`, `SameSite=Lax` 쿠키 확인

### 접근 차단

| 항목 | 결과 |
| --- | --- |
| 비로그인 계정 조회 | HTTP 401 |
| 잘못된 OAuth `state` | 실패 화면으로 이동 |
| 웹훅의 잘못된 인증 키 | HTTP 403 |
| 실패 시 공급자 오류 상세 노출 | 차단 확인 |

### 웹훅 시험 요청

실제 계정이 없는 가상 카카오 회원번호로 웹훅 요청을 전송했다.

| 항목 | 결과 |
| --- | --- |
| 요청 환경 | 공개 HTTPS |
| 인증 | 운영 서버의 실제 웹훅 인증 |
| 응답 | HTTP 200 |
| 측정 응답 시간 | 154ms |
| 후속 정리 작업 | 완료 확인 |

이 요청은 직접 생성한 시험 요청이며, 카카오에서 발송한 실제 연결 해제 이벤트는 아니다.

154ms는 해당 요청 한 번의 측정값이다.

DB 장애나 높은 서버 부하 상황에서도 같은 응답 시간이 보장된다는 뜻은 아니다.

- 모바일 브라우저의 전체 계정 흐름
- 계정 탈퇴 및 관련 권한 회수 정책

검증 기록이 없는 항목은 구현 또는 운영 완료로 단정하지 않는다.

## 문서 관리 기준

이 문서는 카카오 로그인 및 마중 계정·사람 연결 기능의 구현과 검증 기록을 설명한다.

다음 항목은 구분하여 관리한다.

- OAuth2 공급자 인증과 마중 서버 세션
- 사람 연결과 차량·픽업 접근 권한
- 로컬 가상 공급자 시험과 실제 카카오 계정 시험
- 공개 HTTPS 시험 요청과 카카오가 발송한 실제 웹훅 이벤트
- 최초 메모리 세션 구현과 이후 JDBC 공유 세션
- 구현·배포·테스트 완료 여부

기능이나 운영 구성이 변경되면 변경 날짜와 관련 커밋, 검증 환경을 함께 기록한다.
