# 카카오 가입과 닉네임 검색·연결

계정·닉네임 검색·연결 기능의 구현과 검증 기록이다. 공개 서버 배포, 가상 공급자 시험, 실제 카카오 계정 시험을 구분해 적는다.

## 로그인

서버에서 Spring Security OAuth2 Client로 인가 코드와 state를 처리한다. 로그인 성공 후 고정된 홈 주소로 이동하며, 브라우저에는 HttpOnly·Secure·SameSite=Lax 서버 세션 쿠키를 사용한다. 세션은 8시간이며 현재 단일 서버 메모리 세션이라 서버 재시작 시 재로그인이 필요하다. 카카오 프로필 이메일·사진·친구 목록은 가져오지 않는다. 사용자 정보 조회에서 받은 카카오 회원번호만 서버 DB의 로그인 연결에 사용한다.

카카오 토큰은 프론트·차량·URL에 반환하지 않는다. 서버 토큰 교환과 사용자 조회에 연결 3초·응답 5초 제한을 둔다. OAuth 실패는 상세 공급자 응답을 노출하지 않고 login=failed로 이동한다. 인증 공급자 토큰은 로그인 처리 후 클라이언트 저장소에서 제거한다.

카카오 인증정보는 운영 서버 환경변수에서 읽는다. 설정을 하지 않은 기본 실행에서는 로그인을 비활성화하고 기존 픽업 API를 유지한다.

| 환경변수 | 용도 |
| --- | --- |
| MAJUNG_LOGIN_ENABLED | 실제 앱 설정을 마친 뒤 true로 설정 |
| KAKAO_CLIENT_ID | 마중 전용 REST API 키, 서버에만 설정 |
| KAKAO_CLIENT_SECRET | 마중 전용 Client Secret, 서버에만 설정 |
| KAKAO_ADMIN_KEY | 연결 해제 통지 확인용 대표 어드민 키, 서버에만 설정 |
| KAKAO_APP_ID | 연결 해제 통지의 대상 앱 확인 |
| KAKAO_REDIRECT_URI | 고정 HTTPS 주소 + /api/v1/auth/callback/kakao |

민감값은 서버의 서비스 환경 파일에만 보관하고 root 소유·600 권한으로 제한한다. 실제 파일은 Git·이미지·웹 정적 디렉터리·차량 앱·CI 출력에 넣지 않는다. 브라우저에서 로그인 시작 시 OAuth client_id가 카카오 인가 URL에 포함되는 것은 표준 동작이다. 이것은 공개 클라이언트 식별자이며 Client Secret과 구분한다. DB 비밀번호·관리자 키도 기존 서버 환경변수를 사용한다. 테스트의 fixture-client/fixture-secret은 로컬 공급자 재현용 문자열이다.

배포용 변수 목록은 `deploy/server.env.example`에 값 없이 둔다. 실제 값은 `/etc/majung/server.env`에서 systemd가 읽으며 저장소 안에 `.env`를 만들 필요가 없다. 서버 환경 파일을 수정한 뒤에는 파일 내용이나 전체 환경변수를 출력하지 않고, 필요한 변수의 설정 여부와 파일 권한만 확인한다. 환경 파일 변경을 적용하려면 서비스 재시작이 필요하다.

2026-10-24 마중 서버에 카카오 REST API 키·Client Secret·리다이렉트 주소를 등록하고 root 소유·600 권한을 확인했다. 전송용 임시 파일은 삭제했다.

2026-10-25 공개 HTTPS 웹훅을 검증한 뒤 `MAJUNG_LOGIN_ENABLED=true`로 변경하고 마중 서비스만 재시작했다. 변경 전 환경 파일은 서버의 접근 제한된 백업 디렉터리에 보관했다. DB 헬스체크와 공개 세션 API의 활성화 상태를 확인했다. 기존 플리플리 서비스 설정은 변경하지 않았다.

## API

| 요청 | 동작 |
| --- | --- |
| GET /api/v1/auth/session | 로그인 설정·본인 프로필·CSRF 토큰 |
| GET /api/v1/auth/login | 설정 완료 시 카카오 인증 시작 |
| POST /api/v1/auth/logout | CSRF 확인 후 세션 무효화 |
| GET /api/v1/accounts/me | 본인 계정·마중 ID·닉네임 |
| PATCH /api/v1/accounts/me | nickname 설정·변경 |
| GET /api/v1/accounts/search?query=...&page=0 | 닉네임 부분 검색 또는 정확한 마중 ID 검색 |
| GET /api/v1/connections?page=0 | 받은/보낸 대기 요청과 연결된 목록 |
| POST /api/v1/connections | memberId 대상으로 연결 요청 |
| POST /api/v1/connections/{id}/accept | 받은 요청 승인 |
| POST /api/v1/connections/{id}/reject | 받은 요청 거절 |
| POST /api/v1/connections/{id}/cancel | 보낸 대기 요청 취소 |
| POST /api/v1/connections/{id}/disconnect | 연결 해제 |

계정 상태 변경 요청은 session 응답의 csrfToken을 X-CSRF-TOKEN 헤더로 보낸다. 세션 쿠키는 같은 HTTPS origin에서 사용한다. 기존 Bearer 픽업·차량 API의 권한을 로그인 세션으로 대체하지 않는다.

## 계정과 검색

마중 ID는 MJ-와 서버 무작위 10자리 16진수 조합이며 DB에서 중복을 막는다. 충돌·동시 최초 로그인은 트랜잭션 롤백 후 재조회·재시도한다. 같은 카카오 계정은 같은 마중 계정·ID를 유지한다. 닉네임은 중복을 허용하고 NFKC 정규화한 문자·숫자·공백·밑줄·점·하이픈 2~20자로 설정한다. 미설정 계정은 검색 결과와 새 연결 요청에서 제외한다.

검색은 로그인한 계정만 이용한다. 검색어 2~32자, 페이지당 20건, 최대 페이지 50의 초기 제한이다. 검색 결과는 memberId·majungId·nickname만 포함한다. 본인은 제외하고 SQL 와일드카드 입력은 문자로 처리한다. 이 검색은 사람을 찾는 기능이며, 검색된 계정이 등록된 차량을 소유하거나 현재 픽업 가능한 운전자임을 보증하지 않는다. 계정과 차량 연결은 후속 구현이다.

## 연결 상태

PENDING → ACCEPTED / REJECTED / CANCELLED, ACCEPTED → DISCONNECTED. 상대의 수락 전 반대 방향으로 요청해도 자동 승인하지 않는다. 동일 두 계정 사이 요청은 정렬된 두 계정 잠금·DB 유일성으로 하나만 유지한다. 받은 사람만 승인·거절하고 보낸 사람만 취소한다. 승인된 연결은 양쪽에서 해제할 수 있다. 상태와 맞는 재전송은 같은 결과를 반환한다. 관계없는 계정에는 404로 응답한다.

거절·취소·해제 직후 반복 요청을 줄이기 위해 재요청에 24시간 간격을 둔 초기 구현값이다. 차단·친구별 수신 설정·영구 차단 UI는 별도 기능이다. 연결은 닉네임이 아니라 계정으로 유지하며 닉네임 변경은 목록에 반영한다.

연결 승인으로 픽업이 생성되거나 위치·ETA가 공개되지 않는다. 연결 링크, 실제 마중 요청·30분 만료·대기 순서·자기 ETA·차량 소유자 연결은 후속 작업이다. 서비스 내 탈퇴 UI와 계정·차량 연결 이후의 권한 회수는 후속 작업이다.

## DB와 시험

새 DB는 initial-schema.sql을 사용한다. 기존 DB는 백업 후 upgrade-member-accounts.sql을 한 번 적용하고 테이블 권한을 설정한다. 열린 차량 등록 PR의 업그레이드 SQL과는 별도다. 해당 코드가 배포된 서버에 이 브랜치만 배포하면 기존 차량 등록 API가 빠질 수 있으므로 통합 후 배포한다.

./gradlew test bootJar: 기존 25개와 새 7개, 총 32개 통과. 새 시험은 로컬 HTTP 공급자와 실제 Spring Security 필터·세션을 사용한다. state의 브라우저 연결·재사용 거절, 로그인 뒤 세션 ID 변경, CSRF·로그아웃, 동명이인·정확 ID·와일드카드, 본인/다른 사람 승인 금지, 동시 가입·동시 요청과 닉네임 변경을 검증한다. 실제 카카오 계정·실제 모바일 브라우저·공개 HTTPS 로그인 시험은 이 결과에 포함하지 않는다.

## 카카오에서 연결을 끊은 경우

`POST /api/v1/auth/kakao/unlink`는 카카오 연결 해제 웹훅 전용이다. 대표 어드민 키 헤더와 앱 ID가 일치해야 `app_id`, `user_id`, `referrer_type` 폼 입력을 받는다. 이 경로에만 브라우저 CSRF 예외를 두고, 나머지 계정 변경 요청에는 CSRF 검사를 유지한다.

통지를 DB에 저장한 뒤 200으로 응답한다. 저장된 통지가 있는 계정은 즉시 기존 세션·재로그인·검색·새 연결 요청에서 제외한다. 5초 주기 작업이 계정과 연결 관계를 한 트랜잭션으로 삭제하고 작업 기록도 지운다. 삭제 중 실패하면 작업 기록을 남겨 다음 주기에 재시도한다. 같은 통지를 여러 번 받거나 이미 삭제된 계정의 통지를 받아도 처리할 수 있다. 실제 데이터가 지워지기 전에도 기존 세션은 사용할 수 없다.

수신 DB 작업에는 2초 트랜잭션 제한을 둔다. 카카오는 3초 내 응답을 요구하므로 실제 배포 환경에서 응답 시간을 추가로 측정해야 한다. DB 저장 자체가 실패하면 수신 완료로 처리하지 않는다. 이 장애는 운영 확인이 필요하며 공급자가 재전송한다고 가정하지 않는다. 카카오 콘솔에 `POST https://majung.cloud/api/v1/auth/kakao/unlink`를 등록했다. 아직 실제 사용자의 연결 해제로 발생한 통지까지 확인한 것은 아니다.

로컬 HTTP 공급자 시험에서 잘못된 키·다른 앱 ID 거절, 중복 수신, 정리 전 접근 차단, 계정·연결 삭제, 재처리와 상대 계정 유지까지 확인했다.

- [카카오 연결 해제 웹훅 명세](https://developers.kakao.com/docs/ko/kakaologin/callback)

## 브라우저 연동 확인 · 2026-10-25

로그인 시작·성공·실패는 고정 상대 경로의 Location 헤더를 사용한다. 프록시의 내부 Host나 HTTP 주소로 브라우저를 이동시키지 않는다. 성공 주소는 `/account`, 실패 주소는 `/account?login=failed`다.

수동 브라우저 시험은 `MAJUNG_BROWSER_FIXTURE=true ./gradlew test --tests '*AccountBrowserFixtureTest'`로 별도 실행한다. API는 loopback 18081, 웹은 `MAJUNG_API_PORT=18081 MAJUNG_WEB_PORT=18082 npm start`로 실행한다. 가상 공급자에서 시험 계정 1·2를 선택하며 실제 카카오 계정이나 키는 사용하지 않는다. 15분 뒤 자동 종료되고 JVM 임시 디렉터리에 `majung-browser-fixture.stop`을 만들어 먼저 종료할 수 있다. 일반 자동 시험에서는 이 수동 시험 한 개를 건너뛴다.

실제 Tomcat·DB·Spring Security와 브라우저에서 두 계정의 닉네임 설정·검색·연결 요청·수락·해제를 확인했다. HTTP·Secure 쿠키 해제는 이 시험 클래스에만 지정돼 있으며 배포 JAR에는 시험 클래스가 들어가지 않는다.


## 공개 HTTPS 검증 — 2026-10-25

- `/api/v1/auth/login`에서 고정된 서버 인증 경로로 302 이동한 뒤 카카오 인가 화면에 도달했다. PKCE의 S256 방식이 포함되고, 인가 주소의 콜백은 등록한 HTTPS 주소와 일치했다.
- 새 로그인 세션 쿠키의 Secure·HttpOnly·SameSite=Lax 설정을 확인했다.
- 로그인하지 않은 계정 조회는 401, 잘못된 state를 가진 실패 콜백은 `/account?login=failed`로 이동했다. 공급자 오류나 키를 화면에 표시하지 않았다.
- 웹훅의 잘못된 인증 키는 403으로 차단했다. 실제 계정이 없는 가상 회원번호를 사용한 정상 요청은 154ms에 200을 반환했고, 비동기 처리 대기 항목이 정리됐다. 이 요청은 운영 서버의 실제 키로 보냈지만 카카오가 발송한 이벤트는 아니다.
- 카카오 동의 화면에서 마중에 제공하는 정보는 회원번호이며 이메일·사진·친구 목록을 요청하지 않았다. 사용자 동의 후 실제 카카오 계정으로 로그인해 마중 ID 발급과 닉네임 저장을 확인했다. 새로고침 후 세션이 유지됐고, 로그아웃 후 다시 로그인해도 기존 ID와 닉네임이 유지됐다. 실제 두 카카오 계정 사이 연결 요청·수락과 서비스 외부 연결 해제 통지 시험은 아직 수행하지 않았다.

수신 시간이 한 번 3초 이내였다는 결과로 DB 장애·서버 부하 상황에서도 같은 시간이 보장된다고 해석하지 않는다. 키·회원번호·쿠키·OAuth state·인가 코드는 기록과 캡처에 넣지 않는다.
