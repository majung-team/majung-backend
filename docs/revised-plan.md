# 현재 개발 및 검증 기준

**기준일: 2026년 10월 28일**

마중 프로젝트는 초기 공동 개발 단계를 거쳐, 2026년 10월 28일부터 송승준이 후속 개발·검증·배포 및 유지보수를 담당한다.

초기 개발 과정에서 안성모와 송승준이 분담한 작업과 실제 작성 코드는 기존 Git 커밋 및 Pull Request 기록에 따라 유지한다. 담당자 변경이 과거 기여 내역의 변경을 의미하지는 않는다.

## 1. 개발 및 기여 기록

- [실제 PR·커밋 기반 개발 현황](https://github.com/majung-team/majung/blob/main/docs/development-status.md): 기능별 구현 내용과 작성 이력
- [현재 서비스 접속·설치·테스트 안내](https://github.com/majung-team/majung/blob/main/docs/team-testing.md): 실행 환경 및 검증 방법
- [초기 기능·역할 분담 계획](https://github.com/majung-team/majung/blob/main/docs/revised-plan.md): 초기 개발 당시의 계획으로, 현재 담당자 배정표는 아님

기능의 구현자와 기여 범위는 문서의 담당자 표기만이 아니라 실제 변경 커밋 및 PR을 기준으로 확인한다.

## 2. 현재 차량 연결 기준

일반 운전자는 차량 화면의 QR코드를 휴대전화로 열어 카카오 로그인 후 최초 연결을 진행한다.

차량에서 운전자 계정을 최종 확인해야 연결이 완료된다.

관리자 일회용 등록 코드는 내부 시험 및 운영 관리 용도로 별도 유지하며, 일반 사용자 연결 절차와 구분한다.

또한 다음 권한은 서로 다른 개념으로 관리한다.

- 차량 등록 및 장치 접근 권한
- 차량과 운전자 계정의 연결
- 개별 픽업의 운전자·탑승자 접근 권한

마중의 차량 연결 기능을 실제 차량 VIN 검증이나 법적 소유권 인증으로 설명하지 않는다.

## 3. 구현·배포·검증 구분

프로젝트 진행 상태는 다음 기준으로 구분하여 기록한다.

| 구분 | 판단 기준 |
| --- | --- |
| 구현 | 소스 코드에 기능 반영 |
| main 반영 | 해당 저장소의 main 브랜치에 병합 |
| 운영 배포 | 실제 서비스 환경에 배포 및 상태 확인 |
| 로컬 검증 | 개발 PC의 서버·브라우저 시험 |
| 에뮬레이터 검증 | 차량용 에뮬레이터에서 동작 확인 |
| 실기기 검증 | 실제 휴대전화 또는 차량용 기기에서 확인 |
| 실차 검증 | 실제 차량 환경에서 확인 |

한 단계의 성공을 다른 단계의 완료로 간주하지 않는다.

예를 들어 에뮬레이터에서 동작한 기능을 실차 검증 완료로 기록하지 않으며, main 병합만으로 운영 배포가 완료됐다고 표현하지 않는다.

## 4. 문서 관리 원칙

기능 변경 시 구현 시점, 실행 환경 및 검증 결과를 함께 기록한다.

과거 테스트 수치와 당시 미구현·미배포 항목은 역사적 기록으로 유지한다. 이후 구현 상태가 달라졌다면 변경 날짜와 근거를 별도로 추가한다.

담당자 변경 이후의 작업은 실제 커밋과 PR을 기준으로 기록하고, 이전 공동 개발 기여 내역은 그대로 보존한다.
